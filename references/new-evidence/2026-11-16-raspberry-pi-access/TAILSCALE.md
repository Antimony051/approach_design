## Register the Pi

The Pi is already registered. If it later needs to be registered again, run on
the Pi and complete the browser login generated by this command:

```bash
sudo tailscale up --hostname=picoscan-pi --accept-dns=false --accept-routes=false --ssh=false
```

These settings retain the Pi's existing DNS configuration, permit incoming
Tailscale connections, and use the existing OpenSSH server for SSH. The Pi does
not advertise subnet routes or act as an exit node.

Verify registration and obtain its Tailscale address:

```bash
sudo tailscale status
sudo tailscale ip -4
systemctl is-enabled tailscaled
systemctl is-active tailscaled
```

## Share the Pi with friends

In the Tailscale admin console, open **Machines**, find **picoscan-pi**, and
choose **Share** from its menu. Create an individual invite link for each friend
and send it to them. A friend installs Tailscale, signs in to their own account,
and accepts their invite. Node sharing gives that recipient access to the Pi;
the tailnet's access policy still controls permitted connections.

For SSH, the applicable policy must permit the intended friend's traffic to
the Pi on TCP port 22. Sharing provides network access; the friend's SSH key
must also be authorized on a Pi account.

## Add a friend's SSH login

Have each friend generate a public key on their own computer if they need one:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_picoscan
cat ~/.ssh/id_ed25519_picoscan.pub
```

Collect their desired Linux username and the complete `.pub` line. Separate
accounts allow each person's access to be managed independently. No friend
accounts or keys have been added yet.

The Pi administrator can create an account with these commands, replacing
`FRIEND` and the public-key line:

```bash
sudo adduser --disabled-password --gecos '' FRIEND
sudo install -d -m 700 -o FRIEND -g FRIEND /home/FRIEND/.ssh
sudo tee /home/FRIEND/.ssh/authorized_keys >/dev/null <<'PUBLIC_KEY'
ssh-ed25519 REPLACE_WITH_THE_FRIENDS_PUBLIC_KEY
PUBLIC_KEY
sudo chown FRIEND:FRIEND /home/FRIEND/.ssh/authorized_keys
sudo chmod 600 /home/FRIEND/.ssh/authorized_keys
```

After accepting the Tailscale share, the friend connects using the address
shown in their own Tailscale client:

```bash
ssh -i ~/.ssh/id_ed25519_picoscan FRIEND@PI_TAILSCALE_IP
```

The existing `antimony` account uses the laptop's existing SSH key and has
passwordless sudo. The commands above create ordinary friend accounts.

## Ethernet maintenance access

The laptop's `picoscan-pi-direct` NetworkManager profile uses local-link IPv4
and IPv6 with no default route. Activate it when this laptop is cabled directly
to the Pi:

```bash
nmcli connection up picoscan-pi-direct
ssh -o IdentitiesOnly=yes -o HostKeyAlias=100.70.49.73 \
    -i ~/.ssh/tcdc_test_key \
    'antimony@fe80::cb69:61b7:5997:6b6d%enp109s0'
```

The direct profile has autoconnect disabled. Eduroam remains the laptop's
internet connection. This wired path permits maintenance even when campus
Wi-Fi prevents connections between wireless clients.
